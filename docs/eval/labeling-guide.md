# 뉴스레터 라벨링 가이드 (bake-off v1)

ADR 0009(LLM 평가 프로토콜)의 사람 라벨 정의서다. 1차 지표(사람 발행 가능률)와 judge 보정은
전부 이 문서의 정의를 따르는 라벨에서 나온다. **라벨링을 시작한 뒤에는 이 문서를 고치지 않는다.**
애매한 사례는 라벨의 `notes`에 적고, 정의를 바꿔야 하면 라벨링을 멈추고 ADR 0009에 Addendum을 남긴 뒤
새 버전 가이드로 처음부터 다시 단다.

- 라벨러: 1명(프로젝트 소유자). inter-rater 신뢰도는 잴 수 없어서 intra-rater 재라벨로 대신한다.
- 분량: 클러스터 라벨 48개(일반 40 + 어려운 사례 8, ADR 0009 A5) + 출력 라벨 120개 + 재라벨 40개,
  약 208개. 한 개에 3~5분이면 10~17시간이다. **한 번에 1시간을 넘기지 않는다** — 피로가 쌓이면
  뒤쪽 출력일수록 엄해지거나 후해진다.
- 예시는 전부 이 문서를 위해 지어낸 문장이다(실제 기사 아님).

## 0. 도구와 순서

```bash
python -m evaluation.llm.labeling_app --run bakeoff-v1      # http://127.0.0.1:8765
python -m evaluation.llm.labeling_app --run bakeoff-v1      # 재라벨: http://127.0.0.1:8765/?round=2
```

1. **클러스터 라벨을 전부 먼저 단다.** 도구가 순서를 강제한다. 출력을 보기 전에 핵심 사실을
   고정해야 커버리지가 출력에 맞춰 역산되지 않는다.
2. **출력 라벨**: 불투명 id와 무작위 순서로만 보인다. 어떤 모델이 썼는지, 자동 검사기(사실성·드리프트)
   결과가 무엇인지는 일부러 보여 주지 않는다. 짐작이 가더라도 짐작을 라벨에 반영하지 않는다.
3. **재라벨**(2차): 1차 라벨 후 48시간이 지나야 열린다. 5절 참고.

라벨은 `data/labels/<run>/`(gitignore)에만 저장된다. 기사 원문을 메모에 길게 옮기지 않는다(저작권).

## 1. 클러스터 라벨

화면 왼쪽의 원문 기사(전체 본문)만 보고 단다.

### 1.1 `single_event` — 하나의 사건인가 (Y/N)

`ClusterEvaluator`의 PASS 기준과 **같은 정의**다. ROC 분석이 이 라벨로 `ClusterEvaluator`의
confidence를 평가하기 때문이다.

- **Y**: 클러스터의 **모든** 기사가 같은 사건이거나, 한 이슈의 밀접한 하위 사건이다. 한 문장으로
  요약할 수 있는 중심 주제가 있다.
- **N**: 서로 무관한 사건이 2개 이상 섞였거나, 이상치(다른 사건 기사)가 **하나라도** 있다.

| 예 | 판정 | 이유 |
|---|---|---|
| ① 삼성전자 평택 HBM 라인 증설 ② SK하이닉스 청주 투자 확대 ③ D램 가격 10% 상승 | Y | "메모리 반도체 투자 확대"라는 한 이슈의 하위 사건 |
| ① ② ③ + ④ 프로야구 개막전 결과 | N (이상치 ④) | ④는 무관한 기사 |
| ① 기준금리 동결 ② 기준금리 동결 후 대출금리 전망 ③ 태풍 북상 ④ 태풍 피해 대비 | N (이상치 없음) | 두 사건이 반반 섞였고 어느 쪽도 주된 사건이 아니다 |
| ① 정부 반도체 지원법 발표 ② 같은 법안 야당 반발 ③ 같은 법안 업계 반응 | Y | 한 사건에 대한 여러 관점 |

- 같은 회사가 나와도 사건이 다르면(예: 삼성전자 HBM 증설 / 삼성전자 노조 파업) 다른 사건이다.
- 같은 날 같은 분야라는 것만으로는 한 이슈가 아니다(예: 코스피 마감 시황 / 특정 기업 실적 발표는
  시황 기사가 그 실적을 중심으로 다루지 않는 한 다른 사건).

### 1.2 `outlier_ids` — 이상치 기사

- 중심 사건과 무관한 기사 id를 모두 체크한다. 이상치가 있으면 `single_event`는 반드시 N이다
  (도구가 막는다).
- 두 사건이 반반 섞여 어느 쪽도 중심이 아니면 이상치를 체크하지 않는다(표의 세 번째 예).
- 판단이 어려우면: "이 기사를 빼면 남은 기사들의 한 문장 요약이 더 정확해지는가?" → 그렇다면 이상치.

### 1.3 `key_facts` — 핵심 사실 3~6개 + 근거 기사 id

생성된 뉴스레터의 **핵심 사실 커버리지** 기준이다.

- **주된 사건이 있으면 3~6개를 적는다** — `single_event=Y`이면 필수이고, N이라도 이상치를 뺀 나머지가
  한 사건이면 적는다. 주된 사건이 없을 때(두 사건이 반반)만 비워 둔다. 1~2개만 적는 것은 허용하지 않는다.
- 사실 하나 = 확인 가능한 문장 하나(누가/무엇을/언제/얼마나). 해석·전망·평가는 넣지 않는다.
- 근거 기사 id는 그 사실을 **직접 적은** 기사를 모두 고른다. 이상치 기사만 근거인 사실은 적지 않는다
  (도구가 막는다).
- 고르는 순서: (1) 여러 기사가 공통으로 전하는 사실 → (2) 사건을 이해하는 데 빠지면 안 되는 수치·주체·시점.
  세부 수치를 사실마다 쪼개지 않는다.

좋은 예 (1.1 표의 첫 번째 클러스터):
1. 삼성전자가 평택 공장에 HBM 라인을 증설하고 2조 원을 투자한다 — 근거 [1]
2. SK하이닉스가 청주 공장에 1조5000억 원을 투자한다 — 근거 [2]
3. 메모리 업황 개선으로 D램 가격이 10% 올랐다 — 근거 [3]

나쁜 예: "반도체 업계가 활기를 띤다"(해석), "삼성전자 투자는 2조 원이다"와 "삼성전자는 평택에 투자한다"를
따로 적기(한 사실을 쪼갬), "HBM은 고대역폭 메모리다"(배경 지식, 이 사건의 사실이 아님).

## 2. 출력 라벨

**평가 대상은 형식체 초안(제목·한줄소개·본문)이다** (ADR 0009 A2). 문체 변환본은 `tone_drift` 하나에만
쓴다. judge v2와 결정론적 검사기가 형식체 초안을 보기 때문에, 보정 대상과 라벨 대상이 같아야 한다.
원문은 왼쪽의 **전체 본문**을 기준으로 한다(생성기는 기사당 앞 1500자만 봤지만, 전체 본문에 있는 사실은
오류가 아니다 — 결정론적 게이트도 전체 본문과 대조한다).

### 2.1 `fact_errors` — 사실 오류 구간

초안에서 틀린 부분을 드래그로 선택하고 유형을 고른 뒤 "사실 오류로 표시". 한 필드 안에서만 선택된다.

**오류다**
- 원문과 **모순**: 원문 2조 원 → 초안 3조 원, 원문 9월 25일 → 초안 9월 26일, 원문 "검토 중" → 초안 "확정".
- 원문에 **근거 없는 구체 사실**: 원문에 없는 수치·날짜·인명·기관명·인용문·인과 주장.
  원문에 없으면 실제로 사실이어도 오류다(judge v2 프롬프트와 같은 기준).
- **지어낸 인용**: 큰따옴표 안의 말이 원문 어디에도 없으면 `quote`. 원문 인용을 요약해 따옴표 없이 쓰면 오류 아님.
- 주체 바꿔치기: 원문 "SK하이닉스가 1조5000억 원" → 초안 "삼성전자가 1조5000억 원" (`entity`).

**오류가 아니다**
- 같은 값의 다른 표기: `1조5000억 원` = `1조 5000억 원` = `1.5조 원`, `1만2000명` = `12,000명`,
  `20%` = `20퍼센트`, `지난해` = `작년`(같은 해를 가리킬 때).
- 원문 수치로 **정확히 계산되는** 값: 두 회사 투자 합계 "3조5000억 원"(2조 + 1조5000억). 계산이
  틀렸거나 원문에 없는 기준을 섞었으면 오류(`number`). 참고로 결정론적 게이트는 원문에 글자로 없는
  계산값을 막는다 — 사람 라벨은 "사실인가"를, 게이트는 "원문에서 확인되는가"를 본다.
- 일반화: "삼성전자와 SK하이닉스" → "국내 메모리 업체들".
- 누구나 아는 배경(예: "반도체는 수출 주력 품목이다"). 단 구체 수치가 붙으면(“수출의 20%”) 근거가 필요하다.

**구간 선택 요령**: 틀린 값만 최소로 고른다("3조 원"). 문장 전체가 지어낸 것이면 그 문장을 고른다.
유형: `number` 수치 / `date` 날짜·시점 / `entity` 인명·기관·회사·지명 / `quote` 인용 / `other` 그 밖(인과·확정 여부 등).

### 2.2 `key_facts_covered` — 핵심 사실 커버리지

클러스터 라벨의 핵심 사실 중 초안에 담긴 것을 체크한다.

- 초안만 읽은 독자가 그 사실을 알게 되면 "담김". 표현은 달라도 된다.
- 수치가 핵심인 사실은 수치가 맞아야 담김이다(2조 원 → 3조 원이면 담기지 않았고, 2.1의 오류이기도 하다).
- 일부만 담기면(주체는 있는데 핵심 수치가 빠짐) 담기지 않은 것으로 본다.

### 2.3 `style` — 문장·구성 품질 1~5

사실 정확성과 커버리지는 **보지 않는다**(각각 2.1, 2.2). judge v2의 `style`·`coherence` 기준과 같은
방향이다(`ai_workspace/workflow/evaluators.py`).

| 점수 | 기준 |
|---|---|
| **5** | 그대로 발행할 수 있다. 객관적 톤, 여러 기사를 하나의 흐름으로 통합, 선정적 표현 없음 |
| 4 | 5에 가깝지만 어색한 문장·반복이 한두 군데 |
| **3** | 손볼 곳이 있다: 기사별 단순 나열이 일부 남음, 문장 반복, 제목이 다소 밋밋하거나 과장 |
| 2 | 여러 군데를 고쳐야 한다: 대부분 나열, 흐름이 끊김, 어투가 섞임 |
| **1** | 발행 불가: 모순·뒤죽박죽, 선정적 표현("충격", "경악", "파문"), 기사 제목을 늘어놓은 수준 |

예: "삼성전자는 투자한다. SK하이닉스도 투자한다. D램 가격이 올랐다."처럼 기사마다 한 문장씩 이어 붙이면 2~3,
"메모리 업황이 살아나면서 두 회사가 HBM 투자를 늘리고 있다. 삼성전자는 …"처럼 원인-결과로 묶으면 4~5.

### 2.4 `publishable` — 발행 가능한가 (Y/N)

"이 형식체 초안을, 사실은 고치지 않고 문장 다듬기 5분 이내로 발행할 수 있는가." 아래 중 하나라도
해당하면 **N**, 아니면 **Y**.

1. 2.1의 사실 오류가 하나라도 있다(유형 무관). 계산이 맞는 합계처럼 "오류가 아닌" 항목은 해당 없음.
2. 핵심 사실의 **절반 이상**이 빠졌다(2.2). 핵심 사실이 없는 클러스터면 이 조건은 건너뛴다.
3. `style`이 1~2다.
4. 제목이나 한줄소개가 본문과 맞지 않거나, 본문에 없는 내용을 약속한다(낚시성 제목).

이 규칙은 라벨러의 판단을 대신하려는 것이 아니라 **날마다 같은 기준**을 쓰려는 것이다. 규칙상 Y인데
직관이 N이면 N으로 두고 `notes`에 이유를 적는다(나중에 기준 차이를 볼 수 있게).

### 2.5 `tone_drift` — 문체 변환이 사실을 바꿨나 (Y/N)

화면 아래 "문체 변환본"을 형식체 초안과 비교한다.

- **Y**: 변환본이 초안의 값·주체·시점·확정 여부를 바꿨거나(2조 원 → 20조 원, "검토 중" → "결정"),
  초안에 없던 사실(수치·이름·인용)을 추가했거나, 핵심 사실을 빠뜨렸다.
- **N**: 말투만 바뀌었다(“~했다” → “~했어요”, 이모지 추가), 부수 세부(두 번째로 언급된 같은 수치, 수식어)가
  압축으로 빠졌다.
- 참고: 자동 게이트(G2)는 초안 전체에서 사라진 수치도 드리프트로 센다. 사람 라벨은 의미 기준이라 둘이
  다를 수 있고, 그 차이가 게이트 정밀도의 측정값이 된다. 자동 결과에 맞추려 하지 않는다.

## 3. 판단이 갈리는 경우

- 원문끼리 수치가 다르면(기사 A 2조 원, 기사 B 2조1000억 원): 초안이 어느 한쪽을 쓰면 오류 아님. 둘을
  섞어 새 값을 만들면 오류.
- 원문이 추측형("~할 전망")인데 초안이 단정("~한다")이면 `other` 오류.
- 제목만 틀리고 본문은 맞으면: 제목의 해당 구간을 오류로 표시하고 `publishable=N`(2.4의 1).
- 초안이 기사 제목을 불릿으로 나열한 형태(생성 실패 폴백으로 보이는 것)면 `style=1`, `publishable=N`.

## 4. 기록 요령

- `notes`는 짧게: 어떤 규칙을 적용했는지, 애매했던 점. 기사 문장을 길게 붙여 넣지 않는다.
- 저장 뒤 같은 항목을 1차 라운드에서 다시 저장하면 마지막 값이 쓰인다(이력은 남는다). **재라벨(2차)을
  시작한 뒤에는 1차 라벨을 고치지 않는다.**

## 5. 재라벨 프로토콜 (intra-rater)

- 대상: `export-blind`가 무작위로 고른 출력 30개 + 클러스터 10개(`data/labels/<run>/relabel.json`).
- 1차 라벨 후 **48시간 이상** 지나야 도구가 연다.
- 재라벨 중에는 1차 라벨, `notes`, 라벨 파일(`*_labels.jsonl`)을 보지 않는다. 도구의 2차 화면은 1차 라벨을
  보여 주지 않는다.
- 이 가이드는 다시 읽어도 된다(정의를 떠올리는 것은 허용). 특정 항목을 기억하더라도 기억이 아니라
  지금의 판단으로 단다.
- 한 번에 끝낸다(여러 날에 나누지 않는다).
- 결과: `publishable`의 intra-rater κ가 0.60 미만이면 ADR 0009 규칙대로 1차 지표를 "신뢰 불가"로 표시한다.
  재라벨을 이유로 1차 라벨을 고치지 않는다.
