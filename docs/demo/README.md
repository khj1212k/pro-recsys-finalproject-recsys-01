# 생성 뉴스레터 데모: E0 실행이 만든 14편 [KR-E0]

실제 수집한 한국어 기사를 사건별로 묶은 클러스터 중 15개(기사 163건)에 생성 파이프라인을 돌린 결과를 그대로 모았다. 손으로 고치거나 추린 것이 없다. 처리 순서대로 14편과 만들지 못한 1건이 모두 들어 있다. 각 뉴스레터 쪽에 서비스 판, 정식 초안, 원문 기사 목록(언론사·제목·원문 링크·발행 시각), 게이트·judge·자동 라벨 결과, 지연·비용이 있다.

**E0가 무엇인가.** 2026-02 팀 종료 이후 처음으로 생성 파이프라인(클러스터 평가, 본문·제목 생성, 사실성 게이트, judge v2, 문체 변환, 문체 드리프트 게이트, 저장)을 코드를 바꾸지 않고 실제 기사에 끝까지 돌려 본 기술 통계 기준선이다. 동결 반출본에서 클러스터 15개를 크기(3-4 / 5-9 / 10+건) 버킷별로 층화 추출해 돌렸다. 가설도 모델 비교도 없고 사람 라벨도 없다. 품질 신호는 자동 라벨러(LLM)의 판단이다.

## 표 읽는 법

- **서비스 판 / 정식 초안.** 서비스 판은 파이프라인이 최종으로 저장한 글이고 친근한 말투로 바꾼 문체 변환본이다. 정식 초안은 변환 전의 형식체 글로, 사실성 게이트와 judge가 검사한 것이다. 14편 중 14편이 첫 시도의 초안을 저장했고 문체 변환이 사실을 바꿔 형식체로 되돌린 것은 0편이다.
- **사실성 게이트.** 초안의 수치와 따옴표 인용이 원문에 있는지 보는 결정론 검사다. 개체명은 참고만 한다. 통과는 사실 검증이 아니다.
- **문체 드리프트 게이트.** 변환본에서 수치와 절대 날짜가 더해지거나 빠졌는지, 고유명사가 더해졌는지 본다(설정 `TONE_DRIFT_BLOCKING_TYPES=numbers,dates,entities_added`).
- **judge v2.** 사실성·커버리지·일관성·문체를 1~5로 채점하고, 모든 기준이 3 이상이며 근거 없는 주장이 0건일 때 PASS다. 점수는 기준 평균을 0~10으로 옮긴 값이다. shadow라 FAIL이어도 저장된다.
- **자동 라벨러.** 정식 초안을 원문(기사당 앞 1,500자)과 대조한 LLM의 판정이다. '발행 가능'은 라벨러 자신의 판단, 사실 오류 0건, 문체 3점 이상, 제목·한줄소개 불일치 없음, 빠진 핵심 사실이 절반 미만임을 모두 만족할 때다([ADR 0009](../adr/0009-llm-eval-protocol-and-preregistered-decision-rule.md) A8.8·A8.13). 사람 라벨이 아니고 정확도는 재지 않았다. 표의 판정은 런 a다. 같은 초안을 같은 라벨러가 다시 라벨한(런 b) 10편 중 2편(`r2-c19`, `r2-c60`)은 발행 가능 판정이 달라 괄호로 덧붙였다.
- **지연·비용.** 지연은 한 클러스터를 처리한 벽시계 시간이다(클러스터 3개를 동시에 돌렸다). 비용은 호출별 원장의 합이다.

## 고르는 규칙

[`scripts/build_e0_demo.py`](../../scripts/build_e0_demo.py)가 E0 run의 저장 기록에서 만든다. 평가 클러스터 15개(warmup 2개는 평가 틀 밖이라 뺀다)마다 파이프라인이 저장한 판을 `news_letter_id`로 찾는다. 서비스 판은 `saved` 행, 정식 초안은 같은 id의 `saved_formal` 행이고, 생성 시도·변환 시도 가운데 저장되지 않은 것은 싣지 않는다. 저장 노드·해시·호출 비용·두 리포트의 합계와 하나라도 어긋나면 아무것도 쓰지 않고 멈춘다. 자세한 규칙은 스크립트 머리말에 있다.

다시 만들려면 메인 체크아웃에서 `python3 scripts/build_e0_demo.py`를 돌린다. 입력은 git 밖(`data/experiments/e0/`, `data/exports/`)에 있고, 호출이 없는 읽기 전용 작업이다.
