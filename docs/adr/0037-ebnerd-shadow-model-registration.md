# ADR 0037: EB-NeRD로 학습한 랭커의 shadow 등록 — `poolneg_mask0`·`poolneg` seed 0, 배포할 때 넘기는 모델 파일, 판정 리포트 대조, 라이선스 범위

> 증거 라벨: 이 문서가 인용하는 성능 수치는 전부 **[EB-NeRD]**(덴마크어 공개 벤치마크, ADR 0013 "A2 결과")다. 한국어 서비스의
> 성능이 아니다. 이 결정은 등록 절차와 대상을 정할 뿐 성능을 주장하지 않는다.

## 상태
채택됨 (2026-10-17). 등록 도구(`scripts/register_ebnerd_shadow.py`)와 그 테스트까지다. **실제 등록은 하지 않았다** — 서빙
API가 도는 배포가 아직 없다(Tier 0는 수집 데이터 플레인만, API는 Tier 1, ADR 0026 결정 1). 등록하면 "결과와 한계" 아래에 날짜·버전·
모델 sha256을 덧붙인다.

> 범위 종결 C-22 (2026-10-18): 유보 - 조건은 서빙 API가 도는 배포와, 등록 전에 사람이 학습한 모델의 사용에 관한 라이선스 조항을 확인하는 것이다(아래 "결과와 한계"). 그때까지 "shadow로 서빙 경로에 올렸다"는 문장을 쓰지 않는다([목록](../design/2026-10-18-scope-closure.md)).

## 컨텍스트
- ADR 0013 "A2 결과"의 E1(a)가 등록한 규칙대로 shadow 주모델을 `ranker_v2_poolneg`에서 `poolneg_mask0`(학습 때 요청의 절반에서
  인기도 5열을 0으로 가린 변형)로 바꿨다. 같은 절의 후속 작업 1이 등록 전에 정할 것을 넷 남겼다: 세 seed 가운데 무엇을 어떻게
  올릴지, EB-NeRD(연구·비상업 라이선스)로 학습한 모델 파일을 서빙 레지스트리에 두는 것이 라이선스 안인지, 이 모델로 ADR 0033의
  parity 게이트를 다시 돌리기, 둘째 shadow 칸(`RECSYS_SHADOW_MAX` = 2)에 `poolneg`와 `ranker_v2_mixed` 중 무엇을 둘지.
- 모델 파일은 M4 판정용 실행의 체크포인트(`models/<arm>_s<seed>.txt`, 실행기가 옆에 쓴 같은 이름의 `.json` 요약)에 있다. 그
  체크포인트는 개발용 Mac의 gitignore된 `data/` 아래에만 있고 저장소에는 없다(ADR 0013 사후 변경 기록 통합 기록 4의 EB-NeRD
  운영 규칙: 저장소 커밋·공개 데이터셋·영구 사본 금지). 이 결정을 쓰면서 그 파일들을 열지 않았다.
- 등록 수단은 이미 있다: `scripts/register_model.py`(ADR 0033)가 열 이름·순서를 서빙 어댑터와 비교하고, 서빙 피처 정의의 지문
  (`recsys_core.serving.SCHEMA_HASH`)을 함께 적고, 기본 역할이 shadow다. 이 스크립트는 넘겨받은 파일이 판정한 그 모델인지는 보지
  않는다.
- 커밋된 판정 리포트(`reports/recsys/ebnerd_v1_2_cold.json`의 `models`)에는 arm·seed마다 학습한 피처 목록과 `best_iteration`이
  있고 모델 파일의 해시는 없다. 리포트에 적힌 `poolneg_mask0`·`poolneg`의 seed 0·1·2 피처 목록은 서빙 어댑터의 22열
  (`recsys_core.serving.FEATURE_NAMES`)과 이름·순서가 같다(`tests/recsys/test_register_ebnerd_shadow.py`의 첫 테스트). 그래서
  "열이 다르면 멈춘다"는 조건에는 걸리지 않는다. 파일 자체의 열은 등록할 때 도구가 다시 본다.
- 학습한 쪽과 서빙 쪽의 **피처 정의는 세 곳이 다르다**(ADR 0033 결정 5가 하네스 기본값을 그대로 두기로 한 것): 단기·세션 창의
  이벤트 상한(학습 없음, 서빙 20개), 아이템 인기도 창의 끝(학습 요청 시각, 서빙 2초 앞), 세션(학습 EB-NeRD `session_id`, 서빙 30분
  간격). 열 이름·순서는 같다. 그래서 등록 행의 스키마 지문은 "이 모델이 채점될 서빙 정의"이고 학습 정의의 지문이 아니다.
- 서빙은 레지스트리에서 role = shadow인 행을 최근 등록 순으로 `RECSYS_SHADOW_MAX`개 읽고, 같은 후보에 점수만 매겨 칸 로그에
  남긴다(응답은 바뀌지 않는다, ADR 0025·0033). 점수는 요청 경로 밖의 전용 스레드에서 자기 예산(500ms) 안에 낸다.

## 검토한 대안
1. **어느 seed를 올릴까**
   - **(가) seed 0 하나 (채택)** — 규칙 하나로 정해지고 seed별 지표를 보지 않고 고를 수 있다. 이 문서는 seed별 지표(`seed_means`)를
     열지 않고 썼다.
   - (나) es 점수가 가장 높은 seed — es는 학습 창 안의 조기 종료 구간이라 판정 데이터는 아니지만, 고르는 단계를 하나 더 만든다.
   - (다) 세 seed 모두 — shadow 칸 2개를 같은 arm이 차지해 둘째 칸(대안 2)이 없어진다. 세 seed는 같은 데이터·같은 구성이라 서로
     비교해 얻는 것이 적다.
   - (라) 세 seed 점수의 평균(앙상블) — 서빙에 여러 모델을 한 점수로 묶는 형식이 없고, 평균한 모델은 E1(a)에서 평가하지 않았다.
2. **둘째 shadow 칸**
   - **(가) 같은 실행의 `poolneg` seed 0 (채택)** — E1(a)가 주모델과 쌍체로 비교한 상대이고, 재현 게이트를 통과한 arm이다. A2 결과
     서술 1에 따르면 인기도가 "없다"가 아니라 "적다"인 조건(유저 서브샘플 12칸)에서는 마스킹 모델이 원 모델보다 낮았다. 한국어 서비스의
     초기는 두 구간을 다 지나므로, 같은 후보에 두 모델의 점수를 나란히 남기면 그 차이를 나중에 서비스 로그로 볼 수 있다.
   - (나) `ranker_v2_mixed` — ADR 0013 결정 2가 함께 기록하기로 했던 절충 모델이다. M4 실행의 arm에 없어(A2.4) 판정 리포트에 대조할
     항목이 없고, 등록하려면 지금 코드로 다시 학습해야 한다. 하지 않는다.
   - (다) 비워 둔다 — 칸 하나를 그냥 버린다.
3. **모델 파일을 어떻게 서빙에 넘길까**
   - (가) 저장소에 커밋 — EB-NeRD 운영 규칙 위반. 기각.
   - (나) API 이미지에 넣기 — 이미지가 공개 레지스트리에 올라가면 공개 사본이 된다. 기각.
   - **(다) 배포할 때 파일을 넘겨 등록 도구로 DB에 올린다 (채택)** — 파일은 체크포인트에서 서빙 DB에 닿는 곳의 임시 디렉터리로
     옮기고(scp, 또는 그 실행의 비공개 버킷에 아직 있으면 거기서 내려받기) 등록한 뒤 지운다. 저장소·이미지에는 들어가지 않는다.
   - (라) 서빙이 실행 중에 비공개 버킷에서 읽기 — API에 버킷 자격 증명과 새 의존성이 생긴다. 지금 필요 없다.
4. **넘겨받은 파일을 무엇으로 확인할까**
   - (가) `register_model.py` 그대로 — 열은 보지만 판정한 그 모델인지, 하네스가 예측에 쓴 반복 수와 같은지는 보지 않는다.
   - **(나) 판정 리포트와 대조하는 래퍼 (채택)** — 아래 결정 2의 다섯 검사.
5. **라이선스**
   - (가) 등록하지 않는다 — 가장 보수적이다. shadow 점수가 없으면 E1(a)의 판정이 서비스에서 아무 데이터도 만들지 않는다.
   - **(나) 비공개 서빙 DB에, 비상업 포트폴리오 배포의 shadow 점수로만 (채택)** — 근거와 조건은 결정 4.
6. **이 모델로 parity 게이트를 다시 돌리는 일**
   - (가) CI가 비공개 버킷에서 모델을 받아 돌기 — CI에 버킷 자격 증명이 필요하고, 공개 저장소의 워크플로 로그에 경로가 남는다.
     지금 하지 않는다.
   - **(나) 게이트 테스트가 `RECSYS_PARITY_MODEL_FILE`의 모델로도 돌게 한다 (채택)** — 모델 파일과 PostgreSQL이 같이 있는 곳에서
     배포하는 쪽이 돌린다. 이 변경에서는 돌리지 않았다.

## 결정
1. **등록 대상**: 주모델 `poolneg_mask0` seed 0, 둘째 칸 `poolneg` seed 0. 모델 이름은 서빙 기본값 `ranker`, 버전
   `ebnerd-v1.2-<arm>-s<seed>`, 역할은 **shadow만**(ADR 0013 결정 4의 활성 조건 — 이 모델로 돈 parity 게이트, 한국어 데이터의 피처
   분포 점검 — 이 남아 있다). 등록 순서는 `poolneg` → `poolneg_mask0`이다(서빙은 최근 등록 순으로 칸을 채우므로 주모델이 첫 칸).
2. **도구** `scripts/register_ebnerd_shadow.py`. 하나라도 어긋나면 아무것도 등록하지 않는다(파일을 전부 검사한 뒤 등록한다).
   1. 모델 파일 옆의 실행기 요약이 있고, 그 arm·seed가 파일 이름과 같고, 결정 1의 arm·seed다(랭크 정규화·축소 CTR·NaN 마스킹 arm은
      받지 않는다).
   2. 요약의 피처 목록·`best_iteration`이 커밋된 판정 리포트의 같은 arm·seed와 같다.
   3. 모델 본문의 트리 수가 `best_iteration`과 같다(하네스는 `best_iteration`까지로 예측했고 서빙은 본문의 트리를 전부 쓴다).
   4. 모델의 열 이름·순서가 서빙 어댑터의 22열과 같다. 다르면 거기서 멈춘다(열을 맞춰 끼워 넣지 않는다).
   5. 파일이 저장소 작업 트리 안에 있으면 git이 추적하지 않고 무시 목록에 걸린 자리여야 한다.
   등록 행의 `metrics`에 판정 리포트 파일의 sha256, 사전 등록 커밋, 코드 SHA, 증거 등급, 학습 환경(LightGBM 4.7.0), 학습 정의와
   서빙 정의의 차이(컨텍스트의 세 곳), 라이선스 범위 문구, 이 ADR의 경로를 적는다. `register_model.py`가 모델 본문의 sha256을 더한다.
3. **파일 공급**: 결정 2의 대안 3 (다). 등록 뒤 서빙 DB의 `model_registry` 행이 Mac 밖의 유일한 사본이다. 그 DB의 덤프도 비공개로만
   둔다(지금 규칙과 같다, `docs/runbook.md` 8).
4. **라이선스 범위**: EB-NeRD는 연구·비상업 전용이다. 이 모델은 이 비상업 포트폴리오 배포에서 shadow 점수(칸 로그)를 내는 데만 쓴다.
   모델 본문은 22개 피처(코사인, 클릭·노출 수, 경과 시간, 카테고리 일치 등)에 대한 분기 임계값과 잎 값뿐이고, EB-NeRD의 기사 텍스트·
   임베딩·사용자 ID·행 데이터는 들어 있지 않으며 모델과 함께 배포하지 않는다. 다음 중 하나가 생기면 행을 retired로 내리고 지운다:
   배포가 상업적 용도가 됨, `model_registry`를 공개 위치로 반출함, 라이선스 원문이 학습한 모델의 이런 사용을 막는다고 확인됨.
5. **parity 게이트**: `tests/integration/test_feature_parity.py`는 `RECSYS_PARITY_MODEL_FILE`이 있으면 그 파일의 모델로 같은 게이트를
   돈다(리포트의 `meta.model_source`에 파일 이름이 남는다). shadow 등록의 조건은 아니다 — shadow는 응답을 바꾸지 않고, 서빙 정의가
   등록 뒤에 바뀌면 지문 검사(`scorer.schema_mismatch`)가 그 모델의 점수를 멈춘다. 활성 전환 논의의 조건이다(ADR 0013 결정 4 (a)).

## 증거
- 판정 리포트의 피처 목록 = 서빙 어댑터 22열(두 arm × seed 0·1·2): `tests/recsys/test_register_ebnerd_shadow.py`
  `test_the_m4_models_named_by_the_adr_were_trained_on_the_adapter_columns`. 리포트의 `best_iteration`은 `poolneg_mask0` 343·371·299,
  `poolneg` 322·354·402다.
- 도구의 검사(합성 22열 LightGBM 모델과 합성 리포트): 같은 파일의 단위 테스트 — 허용하지 않은 arm·seed, 요약·리포트의
  `best_iteration` 불일치, 트리 수 불일치, 열 순서 불일치, 23열 모델(어댑터 검사에서 멈춤), 요약 없음·이름 불일치, 작업 트리 안의
  무시되지 않는 자리·추적되는 파일, `--dry-run`, 둘째 파일이 거절되면 아무것도 등록되지 않음.
- DB에 쓰는 부분: `tests/integration/test_register_ebnerd_shadow.py`(CI의 PostgreSQL) — 두 행이 shadow로 들어가고 서빙의
  `SqlModelSource.shadow_versions`가 주모델을 첫 칸으로 읽는다, 거절된 실행은 행을 남기지 않는다.
- 학습·서빙 정의의 차이는 도구가 `recsys_core.features.FeatureConfig()`(하네스 기본값)와 `SERVING_FEATURE_CONFIG`를 비교해 계산한다:
  `short_max_events` None → 20, `item_lag_s` 0 → 2, 세션. 나머지(반감기, 창 길이, CTR 창 등)는 같다.

## 결과와 한계
- **등록하지 않았다.** shadow 점수는 아직 한 건도 없다. 등록 절차는 `docs/runbook.md` 9-1에 있다.
- seed 0 하나만 올린다. E1(a)는 세 seed 지표의 평균으로 판정했고 seed 0 하나는 따로 판정하지 않았다.
- 서빙에서 이 모델이 받는 피처는 학습 때와 세 곳의 정의가 다르다(컨텍스트). 그 차이가 점수에 주는 영향은 재지 않았다. 한국어 서비스의
  클릭·노출 수 척도는 EB-NeRD와 다르고, 척도를 없애는 변형은 E3에서 불충족이었다(ADR 0031 결정 2) — shadow 점수를 해석할 때의 전제다.
- 넘겨받은 파일이 판정한 그 모델이라는 확인은 피처 목록·`best_iteration`·트리 수의 일치이지 암호학적 대조가 아니다(리포트에 모델
  파일의 해시가 없다). 등록할 때 모델 sha256을 행에 남기므로 그 뒤의 대조는 그 값으로 한다.
- **라이선스 원문은 이 결정에서 다시 읽지 못했다.** 근거는 ADR 0013 통합 기록 4(2026-09-26의 재확인)이고, 데이터셋 사이트에 이 작업
  환경에서 접근하지 못했다. 학습한 모델의 사용에 관한 조항은 등록 전에 사람이 확인해야 한다.
- 실제 모델(트리 약 300~400개)로 shadow 점수를 내는 시간은 재지 않았다. 전용 스레드의 예산(500ms)을 넘기면 그 요청의 shadow 점수는
  버려지고 `shadow.*` 카운터에 남는다.
- 이 모델로 돈 parity 게이트는 아직 없다(결정 5). (범위 종결 C-22: 유보)
