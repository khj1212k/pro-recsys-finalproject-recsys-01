# ADR 0002: 뉴스 클러스터링에 HDBSCAN 사용

## 상태
채택됨

## 컨텍스트
매일 여러 언론사에서 수집한 기사를 같은 이슈끼리 묶어야 한다. 이때 다음 제약이 있다:

- 그날 발생하는 고유 이슈의 개수를 사전에 알 수 없다 (클러스터 개수 K가 가변적)
- 이슈별로 다뤄지는 기사 밀도가 크게 다르다: 속보성 이슈는 여러 언론사가 동시에 비슷한 기사를 쏟아내 임베딩 공간에서 조밀하게 뭉치고, 일반 이슈는 소수 기사만 흩어져 존재한다
- 어떤 이슈에도 속하지 않는 단발성 기사(노이즈)를 명시적으로 걸러내야 한다

## 검토한 대안
- **K-means**: 클러스터 개수 K를 미리 정해야 하는데, 이슈 개수가 매일 달라지는 이 도메인에는 근본적으로 맞지 않는다. 노이즈(어디에도 속하지 않는 기사) 개념도 없어 모든 기사가 강제로 어떤 클러스터에 배정된다.
- **DBSCAN**: K가 필요 없고 노이즈를 `-1`로 명시적으로 분리한다는 점은 적합하지만, 전역 단일 `eps`(밀도 반경) 하나로 모든 클러스터를 판단한다. 속보성 이슈(조밀)와 일반 이슈(희소)가 같은 배치 안에 공존하면 하나의 `eps`로는 둘 다 잘 잡아내기 어렵다.
- **HDBSCAN**: 계층적 밀도 기반 클러스터링으로, 클러스터마다 다른 밀도를 허용하면서도 K를 미리 정하지 않고 노이즈를 자연스럽게 분리한다. 위 두 제약을 동시에 만족한다.

## 결정
1차 클러스터링에 HDBSCAN(`core/clustering/hdbscan_clusterer.py`)을 사용한다.

여기에 더해, HDBSCAN 1차 결과가 여전히 서로 다른 이슈를 하나의 클러스터로 합쳐버리는 경우(혼합 주제 클러스터)를 잡아내기 위해 `core/clustering/split_v2.py`의 2차 분할 로직을 추가했다:
- 클러스터 크기가 3인 경우: 이상치 거리비/델타 기반 판정
- 4개 이상인 경우: KMeans 2-way 분할 + silhouette score + 기사 제목의 개체명(Kiwi 형태소 분석) Jaccard 유사도 + 중복 제목 비율을 결합한 다중 신호 스코어링
- VETO(강제 거부) → FORCE(강제 분할) → 가중치 점수 순으로 우선순위를 둬서 단일 신호의 오판을 완화

## 결과
**긍정적:**
- 클러스터 개수를 미리 정하지 않고도 이슈별 밀도 차이를 흡수
- 단순 임베딩 거리 기준 분할보다 정교한 2차 분할로 혼합 주제 클러스터를 실제로 잡아냄

**부정적/한계 (리뷰에서 발견, 아직 미해결):**
- CLI(`--min-cluster-size`)/설정(`config/settings.py`의 `HDBSCAN_MIN_CLUSTER_SIZE`)으로 지정한 값이 `NewsClusterer.cluster_news()`에 실제로 반영되지 않는 배선 버그가 남아있다 — 현재는 생성자 시점의 기본값(3, 2)이 항상 쓰인다. 하이퍼파라미터 튜닝을 통한 클러스터 품질 개선을 실험하려면 이 배선부터 고쳐야 한다(우선순위: 다음 스프린트).
- `split_v2.py`의 임계값(`VETO_JACCARD_TH=0.55` 등)이 상수로 하드코딩되어 있고, 실제 데이터 기준 근거(EDA)가 코드 주석 밖에 문서화되어 있지 않다.
