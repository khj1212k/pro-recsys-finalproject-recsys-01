# 03. LLM 생성 첫 실측: E0 기준선, 지출 원장, 사실성 게이트, 자동 라벨과 그 한계

| | |
|---|---|
| 데이터 | [KR-E0] 한국어 수집 기사 동결 반출본(2026-10-17 반출)에서 클러스터 크기 버킷(3-4 / 5-9 / 10+건)별로 5개씩 층화 추출한 15개 클러스터(+ warmup 2). 기사·초안 텍스트는 저장소에 없고 id·건수·집계만 있다 |
| 증거 등급 | `descriptive`(가설·결정 규칙이 없는 기술 통계 기준선). 절차는 실행 전에 등록했다 |
| 팀과 개인 | 팀 시절 LangGraph 생성 워크플로우와 프롬프트는 내가 담당했다(팀 소개 표 기준). 이 글의 실측 하네스, 사실성 게이트, 지출 원장, 자동 라벨은 팀 이후의 개인 작업이다 |
| 한 줄 | 2월 이후 처음으로 생성 파이프라인이 실제 한국어 기사 15클러스터 위에서 끝까지 돌았다(14 생성, 비용 $0.155614). 사람 라벨 없이 얻은 품질 신호는 자동 라벨러의 판단이고, 그 정확도는 재지 못했다 |

## 문제

생성 파이프라인은 2026-02 팀 종료 이후 한 번도 끝까지 돈 기록이 없었다. 모델 HyperCLOVA X가 더는 쓸 수 없어 어댑터를 바꿨고, 사실성 게이트와 judge v2를 만들었지만 전부 합성 변형·가짜 전송 계층·단위 테스트로만 확인한 것이었다. 모델 선정 실험(bake-off v1)은 사람 라벨링 10~17시간과 곧 은퇴할 수 있는 judge 후보(Haiku 4.5)를 전제로 설계되어 있었고, 결과가 없다. 비용, 지연, 스키마 통과율, 실패 유형, 게이트 차단율이 모두 "없음"이었다.

## 가설

없다. 이것이 의도다. 비교할 팔도 이길 규칙도 없이, 현행 코드가 실제 기사에서 무엇을 하는지 기술 통계로 먼저 남긴다(ADR 0009 A8). 이후 모델 선정이나 프롬프트 변경의 출발점이 되는 숫자를 만드는 일이다.

## 측정 설계

- **코드를 바꾸지 않는 실행.** main의 생성 파이프라인을 프롬프트·temperature·max_tokens·재시도·타임아웃 변경 없이 그대로 돌렸다. 계측은 호출 래퍼와 HTTP 훅으로만 붙였다. 운영 DB 대신 파일 대역을 쓴 것을 포함해 이탈 8가지를 실행 전에 선언했다(ADR 0009 A8.2).
- **표본과 순서의 사전 등록.** 클러스터 표본(시드 `20261006`)·처리 순서·판정 지표·상한·중단 규칙을 실행 전에 커밋했고, 실행 전 기록은 `PYTHONHASHSEED=0`으로 다시 확정했다(A8.11). 리포트를 연 시점이 첫 열람이다.
- **지출 원장.** 요청을 보내기 전에 최악 비용을 예약하고, 런·일·전체 상한에 닿으면 멈춘다. 원장이 지출을 증명하지 못하면 호출을 거부한다([ADR 0035](../adr/0035-llm-spend-cap-in-client-ledger.md)). E0는 유효 실행 상한 $1.00, 누적 상한 $1.50 안에서 돌렸다. 이 설계의 증거는 그때까지 가짜 전송 계층 테스트뿐이었고, E0가 첫 실제 호출이다.
- **사람 라벨 대신 자동 라벨러.** 사람 라벨(예상 약 3.7시간)을 하지 않기로 하고 별도 모델(`gemini-3-flash-preview`)이 클러스터·출력·커버리지·문체를 라벨하게 했다. 결과를 본 뒤의 변경이라는 사실과 라벨러 선정 규칙, 비용 상한 $0.50을 같은 날 ADR 0009 A8.13에 적었다.

| 첫 시도 스키마 통과 | 72/72 = 1.000 [0.949, 1.000]. 재시도 0, HTTP 429 0 |
| 지연 | 클러스터당 벽시계 중앙값 9.3초(최댓값 11.6초). n이 작아 p95는 적지 않았다 |
| 비용 | 원장 합 $0.155614(≈₩218, 가정 환율 ₩1,400/$). 클러스터당 중앙값 $0.0077. 사전 기대값 ≈$0.54보다 작았다(재시도가 0이었고 thinking 토큰이 보고되지 않았다) |
| 분량·형식 규칙 위반(shadow) | 본문 글자 수 11/14 = 0.786 [0.524, 0.924], 문단 수 9/14 = 0.643 [0.388, 0.837], 제목 15자 초과 3/14 |

**사실성 게이트.** 첫 초안에서 미지원 수치 ≥1은 0/14 [0.000, 0.215], 미지원 인용 ≥1도 0/14, 문체 드리프트 차단 0/14였다. 게이트가 막은 것이 없었다는 뜻이다. 막을 것이 없었기 때문인지 놓쳤기 때문인지는 이 숫자로 가려지지 않는다. 게이트의 표기 강건성은 합성 변형으로 확인했다(동치 재표기 오탐 0/494, 수치 ×1.1 변조 검출 500/500, [ADR 0010](../adr/0010-faithfulness-gate-and-judge-v2.md)). 게이트가 막는 유형은 수치와 인용뿐이다. 날짜는 추출만 하고 개체명은 참고로 기록한다.

**자동 라벨 ([`e0_auto_labels_v1`](../../reports/llm/e0_auto_labels_v1.md), 사람 라벨 없음).**

| 항목 | 값 |
|---|---|
| 한 사건 클러스터(single_event) | 11/15 = 0.733 [0.480, 0.891] |
| 발행 가능률(저장본 / 전체 15) | 11/15 = 0.733 [0.480, 0.891] |
| 사실 오류 ≥1 | 3/14 = 0.214 [0.076, 0.476] (유형: 날짜 1, 기타 2) |
| 핵심 사실 커버리지 | 58/74 = 0.784 [0.677, 0.862] |
| 라벨러 대 judge v2 | judge PASS 4/14. 둘의 불일치 7건은 전부 judge FAIL·라벨러 발행 가능. κ(참고) 0.20 |
| 두 번 라벨한 자기 일관성(런 a 대 b) | 발행 가능 8/10 = 0.800 [0.490, 0.943], κ(참고) 0.41 |
| 비용 | $0.328228(상한 $0.50). 원장 누계 $0.483842(E0와 합산) |

라벨러가 센 사실 오류 3건은 모두 수치·인용 밖의 유형이다. 그 때문에 첫 초안에 수치·인용 게이트를 통과한 오류가 있었는지는 "라벨러가 센 수치·인용 오류 0건"으로만 말할 수 있다. 게이트가 막지 못하는 영역에 오류가 있다는 신호이고, 게이트의 정밀도·재현율은 아니다. 클러스터가 크기 버킷별로 3~4건·5~9건·10건 이상으로 나뉘어도 발행 가능률은 0.75~0.80으로 비슷했지만(버킷당 n = 4~5), 이 크기로는 차이를 말할 수 없다.

## 결정

1. **모델 비교보다 완주 기록을 먼저 만들었다.** 한 번도 끝까지 돌지 않은 파이프라인을 두고 비교 실험을 설계하면, 비교가 실패 유형 때문에 흔들린다. 코드를 그대로 두고 기술 통계만 만든 덕분에 이후 프롬프트 수정, 알려진 결함(C2 연결 정합, C4 저장 sentence 드리프트) 수정, 모델 선정의 효과를 이 기준선과 비교할 수 있다. 저장본 14개 중 1개(0.071 [0.013, 0.315])에서 제외된 기사가 연결된 C2 결함이 처음으로 실제 출력에서 관측됐다.
2. **지출은 요청 전에 예약하는 원장으로 묶고, 청구와의 대조는 못 했다고 적었다.** 선불 잔액이 ₩8,000이라 한 번의 폭주가 치명적이다. 원장 합은 87개 HTTP 시도의 응답 usage 합과 같았다. 그러나 청구 잔액은 반영 지연 탓에 대조하지 못했고 곧이어 같은 결제 계정으로 라벨러 호출이 나가 "대조 불가"가 되었다. 원장 값은 청구액의 증거가 아니다.
3. **사람 라벨 없이도 갈 길을 만들되 "자동 라벨러의 판단"이라고 부른다.** 라벨러·생성기·judge가 모두 Gemini 계열이라 일치는 독립 검증이 아니고, 불일치 7건이 한쪽으로 쏠려 라벨러가 관대한지 judge가 엄격한지 모른다. 그래서 리포트 끝에 "계산하지 못한 것" 목록(사람 발행 가능률, judge 보정, 검사기의 정밀도·재현율, 라벨러 정확도)을 두고, 발행 가능률 등을 "사람이 검증한 품질"이라고 쓰지 않는다.

## 한계

- 사람 라벨이 없다. 발행 가능률 0.733과 사실 오류 0.214는 자동 라벨러의 판단이고, 그 정확도는 정답이 없어 재지 않았다. judge v2 보정과 게이트의 정밀도·재현율도 측정하지 않았다.
- n이 클러스터 15개, 출력 14개다. 구간이 넓다(발행 가능률 [0.480, 0.891]). 가설 검정은 없다.
- 라벨러는 요청받은 가장 강한 모델이 아니라 비용 상한 $0.50 안에서 선정 규칙이 고른 preview 모델이고, 기사당 앞 1,500자만 보았다. 이 창이 수치를 어느 쪽으로 치우치게 하는지는 정하지 못했다(처음 쓴 방향 서술은 A8.14에서 정정했다). 라벨러의 응답 모델 버전이 등록한 버전으로 고정됐는지도 확인하지 못했다.
- 생성기 `gemini-3.5-flash-lite`의 한 가지 설정, 한 번의 실행이다. 모델 선정(bake-off) 결과는 없다. 프롬프트는 팀 시절과 같고 분량 규칙 위반이 11/14라는 사실이 다음 프롬프트 수정의 출발점일 뿐, 수정의 효과는 측정하지 않았다.
- 파일 대역 등 이탈 8가지가 있다. 뉴스레터 임베딩 시간은 빠져 있고, 일일 생성(`generate` 잡)은 운영에서 꺼져 있다. 운영 지출과 배포 환경에서의 지연은 측정하지 않았다.
- 기사 본문과 생성 초안은 ADR 0023 때문에 저장소에 없다. 독자가 초안을 직접 읽어 품질을 판단할 수는 없다.
